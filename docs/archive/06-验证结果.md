# 06 · 验证结果

**验证日期**：2026-10-23
**验证目标**：[05-待验证问题](05-待验证问题.md) 第 3 条 —— ASR 会不会自动纠正语法错误
**结论**：✅ **不会。核心风险排除。** 但暴露出两个新的问题，见 §3。

---

## 1. 验证方法

用 macOS `say` 合成 4 段测试音频，每段植入一种已知问题，转 16k 单声道 wav 后送三家 ASR：

| 样本 | 内容 | 植入的问题 | 音色 |
|---|---|---|---|
| `s1_very` | I very like this coffee. | `very` 修饰动词（搭配错误） | Samantha（美音） |
| `s2_accent` | 同上 | 同上 + 中文口音 | Tingting（普通话音色） |
| `s3_tense` | Yesterday I go to the store and buy a coffee, but they don't have oat milk. | 时态错误 `go`/`buy` | Samantha |
| `s4_filler` | Um, I was, uh, think about... the, the project. | 填充词 + 自我修正 | Samantha |

三家模型：`FunAudioLLM/SenseVoiceSmall`、`Qwen/Qwen3-ASR-1.7B`、`XingChenAGI/XingChenASR-V3.2`（SiliconFlow）。

---

## 2. 结果

### 2.1 自动纠错 —— 没有发生

| 样本 | 期望 | 实际 |
|---|---|---|
| `s1_very` | 保留 `I very like` | 三家全部原样返回 `I very like this coffee.` ✅ |
| `s2_accent` | 保留 `I very like` | 两家原样返回 ✅ |
| `s3_tense` | 保留 `I go` / `I buy` | Qwen 原样返回 ✅ |
| `s4_filler` | 保留 um / uh / the the | Qwen 保留 `Um, I was ah, think about the the project.` ✅ |

**这一条是关键**：如果 ASR 把 `I very like` 悄悄改成 `I really like`，整个「发现错误」的链路就废了。三家都没有这么做。

### 2.2 延迟

| 模型 | 首次（冷启动） | 稳定后 | 备注 |
|---|---|---|---|
| `Qwen/Qwen3-ASR-1.7B` | 0.40s | **0.27–0.57s** | 最快，推荐 |
| `XingChenASR-V3.2` | 0.87s | 0.61–0.71s | 次之 |
| `SenseVoiceSmall` | **28.5s** ⚠️ | 未测 | 冷启动极慢，不适合实时 |

Qwen 的延迟完全在预算内（原设计给 ASR 留了 400–1200ms）。

## 3. 新发现的问题

### 3.1 🔴 三个模型都没有返回词级时间戳和置信度

这是**比自动纠错更麻烦的问题**。原设计里有两个核心功能依赖它：

| 功能 | 依赖 | 现状 |
|---|---|---|
| 长停顿检测（`longPausePerMin`、`pausePositions`） | 词级 start/end | ❌ 拿不到 |
| 可疑词挑选（低置信度实词 → 跟读关卡） | 词级 confidence | ❌ 拿不到 |
| 卡壳点识别（停了 4 秒） | 词级时间戳 | ❌ 拿不到 |

三个接口的返回都只有 `{text, duration, language}`，**没有 `words[]`**。

`response_format=verbose_json` + `timestamp_granularities[]=word` 那一轮测试因余额耗尽没跑完（HTTP 402），**这一项还没排除**。普通 OpenAI 兼容接口支持这两个参数，值得先测。

**如果确认不支持，有三条退路**：

1. **换引擎**：Whisper 自建（`faster-whisper`，本地跑，有 word timestamp + 置信度，零 API 成本）
2. **强制对齐**：拿到文本后用 `whisperx` / `ctc-forced-aligner` 补词级时间戳
3. **降级指标**：放弃停顿位置分析，只保留「整体语音时长 → WPM」这一个指标。**不推荐**——卡壳点是整个产品最有价值的数据，丢了就退化成普通陪聊

> 我倾向方案 1 或 1+2 组合。本地 Whisper 还有两个额外好处：不用按分钟付费、音频不出本机。

### 3.2 🟡 ASR 误识别会被误判成用户错误

`XingChenASR-V3.2` 的两个错误：

| 原句 | 识别成 | 后果 |
|---|---|---|
| `oat milk` | **`old milk`** | 会当成用户读错了词 |
| `Um, I was` | **`Come i was`** | 会当成语法错误，加进 `flags` |

Qwen 两个都识别对了。

**这说明模型之间有明确的优劣差**。同时说明流程里需要一道**「回听确认」**：`flags` 里 severity ≥ 2 的项，在复盘时用原始音频再核一遍（人工或二次 ASR），避免把引擎的锅算到用户头上。

对自用场景，最简单的办法是：复盘发出前自己扫一眼，明显是 ASR 听错的直接删掉。

### 3.3 🟡 填充词会被保留 —— 好消息，但要显式确认

Qwen 完整保留了 `Um`、`ah`、`the the`。这是好结果——很多 ASR 引擎会默认清洗掉填充词，那样 `fillerPer100w` 指标就永远算不准。

但 `ah` vs `uh` 的区分不稳定（原文是 `uh`，识别成 `ah`）。所以填充词统计要**按类别合并**，不要细分到具体哪个填充词。

## 5. 复现方式

测试音频在 `probe/audio/`，凭据读取路径：

```bash
SF=$(grep -m1 '^SILICONFLOW_API_KEY=' ../English-Tutor-Agent/.env | cut -d= -f2-)

# 转码（本机没有 ffmpeg，借用 animations 项目里的 ffmpeg-static）
FF=../animations/itch/tools/node_modules/ffmpeg-static/ffmpeg
$FF -y -i in.aiff -ar 16000 -ac 1 -c:a pcm_s16le out.wav

# 转录
curl -s https://api.siliconflow.cn/v1/audio/transcriptions \
  -H "Authorization: Bearer $SF" \
  -F "file=@out.wav" -F "model=Qwen/Qwen3-ASR-1.7B"
```

> SiliconFlow 账户 2026-10-23 余额耗尽（HTTP 402）。继续测需要充值，或改用本地 Whisper。
