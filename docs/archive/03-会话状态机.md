# 03 · 会话状态机

整个 v1 的体验核心。语音管线是确定性的工程量，状态机才是「像不像一个陪练」的分水岭。

---

## 一、状态定义

| 状态 | 含义 | 谁在等 |
|---|---|---|
| `IDLE` | 无进行中会话 | 等用户说第一句 |
| `SCENARIO` | 正在确认场景 / 难度 | 等用户确认或改口 |
| `LISTENING` | 已发出 bot 语音，等用户开口 | 等用户语音 |
| `THINKING` | 收到用户语音，管线在跑 | 等管线 |
| `WRAPPING` | 已说收尾话，等复盘生成 | 等复盘 |
| `POSTMORTEM` | 复盘已交付，等用户点「练发音」 | 等卡片动作 |
| `SHADOWING` | 已发跟读词，等用户跟读 | 等用户语音 |
| `SCORING` | 在跑发音评估 | 等评估 |
| `ARCHIVED` | 会话归档，回到 `IDLE` | — |

> `THINKING` / `SCORING` 是**内部状态**，用户看到的是 emoji reaction + 等待。状态机里区分它们，是为了做超时和淘汰。

---

## 二、事件

| 事件 | 载荷 | 来源 |
|---|---|---|
| `USER_AUDIO` | `{fileKey, durationMs, messageId}` | `im.message.receive_v1` |
| `USER_TEXT` | `{text, messageId}` | 同上 |
| `CARD_ACTION` | `{action, value}` | `card.action.trigger` |
| `TURN_DONE` | `{reply, flags, stuck, signal}` | 管线 |
| `SEND_DONE` | `{messageId}` | 发送层 |
| `SEND_FAILED` | `{error}` | 发送层 |
| `BEATS_ALL_DONE` | — | LLM `advance` 累积 |
| `USER_END` | — | `/end` 或短句关键词 |
| `IDLE_TIMEOUT` | — | 定时器 10 min |
| `HARD_LIMIT` | — | 30 轮 / 15 min |
| `PM_READY` | `{postmortem}` | 复盘生成器 |
| `SCORE_READY` | `{words[]}` | 发音评估 |
| `SUPERSEDE` | `{newEvent}` | 新语音到达（淘汰在跑的 turn） |

---

## 三、转移表

```
IDLE ──USER_AUDIO──────────────> SCENARIO    （开场：先确认练什么）
IDLE ──USER_TEXT(/start X)────> THINKING     （直接指定场景，跳过确认）

SCENARIO ──USER_AUDIO─────────> THINKING     （用户说"我想练面试"）
SCENARIO ──CARD_ACTION(场景)──> THINKING     （点了场景卡片）
SCENARIO ──IDLE_TIMEOUT───────> IDLE

THINKING ──TURN_DONE──────────> （生成语音）→ LISTENING
THINKING ──TURN_DONE(wrap_up)=> WRAPPING
THINKING ──TURN_DONE(end)─────> WRAPPING
THINKING ──SUPERSEDE──────────> THINKING     （重新规划，见 §5）
THINKING ──超时 30s───────────> LISTENING    （降级：发文字提示，保持会话）
THINKING ──SEND_FAILED────────> LISTENING    （文字兜底）

LISTENING ──USER_AUDIO────────> THINKING
LISTENING ──USER_END──────────> WRAPPING
LISTENING ──BEATS_ALL_DONE────> WRAPPING     （通常已在 TURN_DONE 里体现）
LISTENING ──IDLE_TIMEOUT──────> WRAPPING     （超时也要给复盘，不能白练）
LISTENING ──HARD_LIMIT────────> WRAPPING
LISTENING ──USER_TEXT(/end)───> WRAPPING

WRAPPING ──PM_READY───────────> POSTMORTEM
WRAPPING ──超时 3 min─────────> POSTMORTEM   （降级：只发卡片，不给文档）

POSTMORTEM ──CARD_ACTION(练发音)─> SHADOWING
POSTMORTEM ──CARD_ACTION(复习)───> SHADOWING  （带历史错词）
POSTMORTEM ──USER_AUDIO─────────> SCENARIO    （直接开始新练习）
POSTMORTEM ──IDLE_TIMEOUT(1h)───> ARCHIVED

SHADOWING ──USER_AUDIO────────> SCORING
SCORING ──SCORE_READY─────────> POSTMORTEM    （贴分数卡片，可再来一次）
SCORING ──超时 20s────────────> POSTMORTEM    （降级：提示再读一次）

ARCHIVED ─────────────────────> IDLE
```

**关键设计**：

1. **`IDLE_TIMEOUT` 在 `LISTENING` 里也走 `WRAPPING`，不是丢弃。** 用户练到一半跑了，回来还有复盘——这比静默消失强得多。
2. **`POSTMORTEM` 里收到语音直接开新练习。** 不用先 `/new`。
3. **`THINKING` 超时降级为文字，不弃单。** 语音挂了也要把对话续上。

## 四、一次练习的完整走位

```
IDLE
 │ 用户："我想练练明天面试"  (voice)
 ▼
SCENARIO
 │ bot 语音："Sure. I'll be the interviewer — first round, about 8 minutes.
 │            I'll keep it realistic. Ready?"
 ▼
LISTENING
 │ 用户："Ready."  (voice)
 ▼
THINKING  → LISTENING
 │ bot（persona=HR）："Hi, thanks for coming in. So, tell me a little about yourself."
 │   beat=intro  状态：pending
 ▼
THINKING  → LISTENING
 │ 用户："I'm a frontend engineer, I have five years experience in a company
 │       which make... making... a CRM system."   ← 卡壳点：which make → which makes / making
 │ bot（重铸，不点破）："Got it — five years on a CRM product. What was your
 │       main piece of work on it?"
 │   beat=intro → done（提到最近经历）
 ▼
 ... （project / followup 两个 beat 依次完成）
 ▼
THINKING
 │ 所有 beats done → LLM 返回 session_signal = "wrap_up"
 │ bot："Alright, that's all I needed. Thanks — give me about half a minute
 │       and I'll send you the breakdown."
 ▼
WRAPPING
 │ 并行：
 │   - TTS 收尾语音已发（上面那句）
 │   - 组装 postmortem.json（不重新调 LLM，攒数据）
 │   - 生成飞书文档
 │   - 挑 3 个跟读词
 ▼
POSTMORTEM
 │ 发卡片（第一批）→ 发文档链接（第二批）
 │ [ 看完整复盘 ]  [ 练 3 个发音 ]
 ▼
（用户点「练 3 个发音」）
 ▼
SHADOWING
 │ bot 发卡片 + 一条示范语音："movie · soundtrack · fantastic"
 ▼
SHADOWING
 │ 用户一条语音读这三个词
 ▼
SCORING → POSTMORTEM
 │ 卡片回帖：movie /v/ 31 分（发成了 /w/）
 │ [ 再练一次 ]  [ 结束 ]
 ▼
ARCHIVED → IDLE
```

## 五、Reducer 伪码

纯函数，输入 `(state, event, ctx)` 输出 `(nextState, effects[])`。所有 I/O 都是 effect，便于测试。

```ts
type Effect =
  | { kind: 'download_audio'; messageId: string; fileKey: string }
  | { kind: 'run_turn'; turns: Turn[] }            // ASR→指标→LLM
  | { kind: 'speak'; text: string; speed: number }
  | { kind: 'send_card'; card: CardJson }
  | { kind: 'write_doc'; postmortem: Postmortem }
  | { kind: 'react'; messageId: string; emoji: string }
  | { kind: 'build_postmortem' }
  | { kind: 'score_shadowing'; words: string[]; audioPath: string }
  | { kind: 'arm_timer'; name: string; ms: number }
  | { kind: 'cancel_timer'; name: string }
  | { kind: 'persist' };

function reduce(s: SessionState, e: Event, ctx: Ctx): [SessionState, Effect[]] {
  switch (s.status) {

    case 'IDLE':
      if (e.type === 'USER_AUDIO')
        return [{ ...s, status: 'THINKING', pending: 'scenario',
                  turns: [newTurn(e)] },
                [react(s, e.messageId, 'OnIt'),
                 download_audio(e.messageId, e.fileKey),
                 arm_timer('turn', 30_000)]];
      break;

    case 'THINKING':
      if (e.type === 'TURN_DONE') {
        const next: SessionState = {
          ...s,
          turns: s.turns.concat({ role: 'bot', text: e.reply }),
          beats: applyBeat(s.beats, e.reply.beat_progress),
          flags: s.flags.concat(e.reply.flags),
          stuck: s.stuck.concat(e.reply.stuck ? [e.reply.stuck] : []),
          turnCount: s.turnCount + 1,
        };
        const effects: Effect[] = [
          cancel_timer('turn'),
          speak(e.reply.say, s.scenario?.difficulty.tts_speed ?? 1),
        ];

        // 结束判定优先级：用户终止 > 目标达成 > 硬上限
        const ended =
          e.reply.session_signal === 'end' ||
          e.reply.session_signal === 'wrap_up' ||
          next.turnCount >= HARD_TURN_LIMIT;

        if (ended) {
          effects.push(arm_timer('postmortem', 180_000),
                       build_postmortem());
          return [{ ...next, status: 'WRAPPING', endReason: e.reply.session_signal },
                  effects];
        }
        effects.push(arm_timer('idle', IDLE_MS));
        return [{ ...next, status: 'LISTENING' }, effects];
      }

      if (e.type === 'SUPERSEDE') {
        // 新语音插进来：把新 turn 追加，重新跑
        const turns = s.turns.concat(newTurn(e.newEvent));
        return [{ ...s, turns, superseded: (s.superseded ?? 0) + 1 },
                [run_turn(turns)]];
      }

      if (e.type === 'TIMEOUT' && e.name === 'turn') {
        return [{ ...s, status: 'LISTENING' },
                [send_text('⚠️ 服务有点慢，刚才那句我记下了，我们继续。'),
                 arm_timer('idle', IDLE_MS)]];
      }
      break;

    case 'LISTENING':
      if (e.type === 'USER_AUDIO') {
        return [{ ...s, status: 'THINKING', turns: s.turns.concat(newTurn(e)) },
                [cancel_timer('idle'),
                 react(s, e.messageId, 'OnIt'),
                 download_audio(e.messageId, e.fileKey)]];
      }
      if (e.type === 'USER_END' || e.type === 'HARD_LIMIT') {
        return [{ ...s, status: 'WRAPPING', endReason: e.type },
                [cancel_timer('idle'), speak(WRAP_LINE, 1),
                 arm_timer('postmortem', 180_000), build_postmortem()]];
      }
      if (e.type === 'TIMEOUT' && e.name === 'idle') {
        // 超时也要给复盘
        return [{ ...s, status: 'WRAPPING', endReason: 'idle' },
                [speak(IDLE_WRAP_LINE, 1), arm_timer('postmortem', 180_000),
                 build_postmortem()]];
      }
      break;

    case 'WRAPPING':
      if (e.type === 'PM_READY') {
        return [{ ...s, status: 'POSTMORTEM', postmortem: e.postmortem },
                [send_card(summaryCard(e.postmortem)),
                 write_doc(e.postmortem),
                 arm_timer('archive', 3_600_000)]];
      }
      if (e.type === 'TIMEOUT' && e.name === 'postmortem') {
        // 文档生成超时：只发卡片
        return [{ ...s, status: 'POSTMORTEM' },
                [send_card(summaryCard(s.draftPostmortem!)),
                 arm_timer('archive', 3_600_000)]];
      }
      break;

    case 'POSTMORTEM':
      if (e.type === 'CARD_ACTION' && e.value.action === 'shadow') {
        return [{ ...s, status: 'SHADOWING', shadowWords: s.postmortem.shadowWords },
                [send_card(shadowCard(s.postmortem.shadowWords)),
                 speak(s.postmortem.shadowWords.join(' · '), 0.9)]];
      }
      if (e.type === 'USER_AUDIO') {
        return [{ ...s, status: 'THINKING', turns: [newTurn(e)], resetScenario: true },
                [react(s, e.messageId, 'OnIt'),
                 download_audio(e.messageId, e.fileKey)]];
      }
      if (e.type === 'TIMEOUT' && e.name === 'archive') {
        return [{ ...s, status: 'ARCHIVED' }, [persist()]];
      }
      break;

    case 'SHADOWING':
      if (e.type === 'USER_AUDIO') {
        return [{ ...s, status: 'SCORING' },
                [download_audio(e.messageId, e.fileKey),
                 arm_timer('score', 20_000)]];
      }
      if (e.type === 'TIMEOUT' && e.name === 'score') {
        return [{ ...s, status: 'POSTMORTEM' },
                [send_text('评估超时了，再读一次？')]];
      }
      break;

    case 'SCORING':
      if (e.type === 'SCORE_READY') {
        return [{ ...s, status: 'POSTMORTEM', scores: e.words },
                [speak(scoreSummaryVoice(e.words), 1),
                 send_card(scoreCard(e.words)),
                 persist(), arm_timer('archive', 3_600_000)]];
      }
      break;
  }
  return [s, []];
}
```

### 几个实现要点

- **`SUPERSEDE` 不暂停播放**。已经发出去的语音收不回来，那就让用户说完再规划。
- **`beats` 的推进只信 LLM 的结构化输出**，不做关键词匹配。`done_when` 的判断写在 prompt 里。
- **`stuck` 与 `flags` 是追加式的**，会话结束时不重新分析。省钱、快、且不会和当时的现场判断打架。
- **`endReason` 必须记下来**。「用户主动结束」和「超时结束」的复盘措辞应该不同：前者可以更完整，后者要短、别让它变成负担。

## 六、幂等

| 操作 | 幂等键 |
|---|---|
| 处理用户语音 | `message_id` |
| 发送 bot 回复 | `session_id + turn_index` |
| 生成复盘 | `session_id` |
| 写复盘文档 | `session_id`（已存在则更新，不新建） |

进程重启时读 `runtime.json` 里的 `{status, turnIndex, sentTurns[]}`，只补未完成的部分。**已发出的语音绝不重发**——重复的语音比没有更让人烦。

## 七、可观测性（v1 就要有）

每次会话落一份 `trace.jsonl`：

```jsonc
{"t":0,    "stage":"event_in",   "messageId":"om_x", "durationMs":4200}
{"t":120,  "stage":"download",   "ok":true,  "bytes":52310}
{"t":300,  "stage":"ffmpeg",     "ok":true,  "ms":110}
{"t":920,  "stage":"asr",        "ok":true,  "ms":620, "tokens":18, "avgConf":0.87}
{"t":950,  "stage":"metrics",    "wpm":112, "longPauses":2}
{"t":1800, "stage":"llm",        "ms":850,  "in":1200, "out":80}
{"t":2500, "stage":"tts",        "ms":700,  "chars":42}
{"t":2650, "stage":"upload",     "ms":250}
{"t":3000, "stage":"send",       "ok":true,  "replyDurationMs":4320}
```

有了这个，调延迟就是从数字里找最贵的环节，不靠猜。
