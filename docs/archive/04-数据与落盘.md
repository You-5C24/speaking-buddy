# 04 · 数据与落盘

参照 agent-os 的做法：JSON 文件 + 目录分片，够用、好查、能直接 git diff。

---

## 一、目录结构

```
speaking-buddy/
├── config/
│   ├── bots.json              # gitignored，真实凭证只放 .env 的变量名
│   ├── scenarios/             # 场景定义，一个场景一个文件
│   │   ├── cafe-1.json
│   │   ├── job-interview-1.json
│   │   └── ...
│   └── prompts/
│       ├── conversation.md    # 对话 system prompt
│       └── postmortem.md      # 复盘生成 prompt（可选，见 §4）
├── data/
│   ├── sessions/
│   │   └── 2026-10-21/
│   │       └── <session_id>/           # 例：20261021-1530-cafe-1-ab12
│   │           ├── meta.json           # 会话元信息 + 结局
│   │           ├── turns/              # 每轮一目录
│   │           │   ├── 001/
│   │           │   │   ├── user.opus   # 原始音频（保留！复盘要回放）
│   │           │   │   ├── user.wav    # 16k 单声道
│   │           │   │   ├── asr.json    # 词级时间戳 + 置信度
│   │           │   │   ├── metrics.json
│   │           │   │   ├── reply.txt
│   │           │   │   ├── reply.opus
│   │           │   │   └── llm.json    # 该轮的完整结构化输出
│   │           │   └── 002/ ...
│   │           ├── postmortem.json     # 复盘结构化数据
│   │           ├── trace.jsonl         # 全链路耗时
│   │           └── runtime.json        # 断点续跑状态
│   ├── shadowing/
│   │   └── <session_id>/
│   │       ├── user.opus
│   │       └── scores.json
│   ├── review-queue.json      # 待复习错词（跨会话）
│   ├── seen-events.json       # event_id 去重（滚动 500 条）
│   └── runtime.json           # 当前活跃会话的指针
└── docs/
```

**为什么一轮一目录**：调试时能直接 `ls` 到第 7 轮，听原声、看转码、翻 LLM 输出，不用翻日志。

**为什么保留原始 opus**：复盘时可以「这是你说的 / 这是标准音」对照播放。这是最有效的反馈形式，成本为零。按 20s/60KB 估，一次练习 10 轮 ≈ 600KB，一年不清理也就几 GB。

## 三、指标

`metrics` 由每轮的 `metrics.json` 聚合而成：

```jsonc
{
  "userTurns": 8,
  "userWords": 142,
  "userSpeechMs": 76000,
  "wpm": 112,

  "pauseCount": 14,
  "longPauseCount": 5,          // > 1.5s
  "longPausePerMin": 3.9,
  "longestPauseMs": 4200,
  "pausePositions": ["clause_start", "clause_start", "mid_sentence", "turn_start", "turn_start"],

  "fillerCount": 9,
  "fillerPer100w": 6.3,
  "fillers": { "um": 5, "uh": 3, "like": 1 },

  "typeTokenRatio": 0.61,
  "newActiveWords": ["clarify", "receipt", "instead"],

  "grammarErrors": 6,
  "errorsPer100w": 4.2,
  "stuckCount": 2
}
```

### 各指标怎么算

| 指标 | 算法 | 说明 |
|---|---|---|
| `wpm` | `userWords / (userSpeechMs/60000)` | 用户轮次的纯语音时长，不含 bot 说话时间 |
| 长停顿 | 相邻词的 `end → start` 间隔 > 1500ms | 需要 ASR 的词级时间戳 |
| 停顿位置 | 按间隔前后词在句中的位置分类 | `turn_start` / `clause_start`（逗号、连词前）/ `mid_sentence` / `clause_end` |
| 填充词 | 正则匹配 ASR 文本中的 um/uh/erm/hmm/like | `like` 只在非「喜欢」语境计（简单规则：前后无名词时计入） |
| 词型/词例比 | `uniqueWords / totalWords` | 词数 < 50 时不可靠，仅供参考 |
| 主动词汇 | 本次用出的词 − 历史所有会话用过的词 | **最直接的进步证据** |
| 语法错误 | LLM `flags` 里 `type === 'grammar'` 的计数 | 按每百词归一 |

> 提醒：不要单独看任何一个。唯一值得设成目标的组合是 **WPM 上升且 errorsPer100w 不上升**。

### 复盘文档模板（飞书文档）

```markdown
# 口语练习复盘 · 10/21 15:30 · 点单

**今天专注**：把「为什么」说清楚
**用时** 8 分 32 秒 · **9 轮** · **语速 112 wpm**

---

## 最该改的一点

> 你说：I very like this coffee
> 改：I **really** like this coffee
> 为什么：very 不能直接修饰动词。用 really，或者换成 like it a lot。

---

## 逐句对照

### 第 1 轮
**你说**：I want one latte please, with... um... oat milk.
**表达**：很好，没有硬伤。
**发音**：latte 重音在 LA，你读成了 la-TTE
**更自然**：Could I get an oat milk latte, please?
🔊 你的原声 · 🔊 标准读法

### 第 3 轮
...

---

## 今天卡住的地方

1. **第 5 轮**，停了 4.2 秒
   想表达「能不能换一杯」，最后换了话题。
   下次直接说：*Could I swap this for something else?*

---

## 指标

| 语速 | 长停顿 | 填充词 | 错误率 | 新用出的词 |
|---|---|---|---|---|
| 112 wpm | 3.9 /min | 6.3 /100w | 4.2 /100w | clarify, receipt, instead |

（对比上次：语速 ↑ 8，错误率 → 持平）

---

## 下次练什么

- 换货/退款类句型 3 个
- 过去式词尾 /t/ /d/
```

> **注意**：`🔊 你的原声` 这块在飞书文档里怎么放音频需要实测（见 [05-待验证问题](05-待验证问题.md) 第 4 条）。备选方案：云盘附件 / 把对比语音单独发成消息 / 用妙记。

## 五、复习队列

```jsonc
// data/review-queue.json
{
  "version": 1,
  "items": [
    {
      "key": "latte",
      "type": "pronunciation",
      "ipa": "/ˈlɑːteɪ/",
      "firstSeen": "2026-10-21",
      "lastSeen": "2026-10-21",
      "attempts": 1,
      "bestScore": 62,
      "dueAt": "2026-10-24",        // 3 天后
      "intervalDays": 3
    },
    {
      "key": "Could I swap this for something else?",
      "type": "phrase",
      "firstSeen": "2026-10-21",
      "attempts": 0,
      "dueAt": "2026-10-22"
    }
  ]
}
```

规则：

- 发音项：`score < 70` 入队，答对一次间隔 ×2，答对两次出队
- 句型项：卡壳点自动入队，下次场景里有权重加成
- 每次开新会话时，从 `dueAt <= today` 的项里挑最多 3 条混进场景

**v1 不需要 SRS 算法**。固定 3 天间隔 + 最多 3 条，够用。真正的失败模式是「队列太长，用户不看」。

## 六、跨会话的「用户档案」

```jsonc
// data/profile.json
{
  "userId": "ou_xxx",
  "sessionsCompleted": 12,
  "firstSessionAt": "2026-10-14",
  "baseline": { "wpm": 96, "errorsPer100w": 6.1, "longPausePerMin": 5.4 },
  "current":  { "wpm": 112, "errorsPer100w": 4.2, "longPausePerMin": 3.9 },
  "recurringIssues": [
    { "pattern": "very + verb", "count": 7, "lastSeen": "2026-10-21" },
    { "pattern": "past tense -ed 词尾丢失", "count": 11, "lastSeen": "2026-10-21" }
  ],
  "strongAt": ["寒暄", "描述事实"],
  "weakAt":  ["礼貌地拒绝", "打断并提问"]
}
```

`recurringIssues` 是复盘里最值钱的东西 —— **同一个错误出现 3 次以上，就不是「这次的问题」，是「你的问题」**。这时候复盘措辞要变：

> ~~今天有一点没做好：very like~~
> → 这已经是你第 7 次用 `very` 修饰动词了。这个要专门练一下。

后者才真的会改。

## 七、清理策略

- `turns/*/user.wav` 转码产物：复盘文档生成后即可删（原 opus 保留）
- `turns/*/reply.opus`：保留 30 天
- `trace.jsonl`：保留 30 天
- 原始 opus + `postmortem.json` + `meta.json`：**永久保留**。这是你的数据资产，也是以后换渠道时唯一带得走的东西。
