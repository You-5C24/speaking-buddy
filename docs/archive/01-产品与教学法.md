# 01 · 产品与教学法

## v1 范围

| 做 | 不做 |
|---|---|
| 单人、单聊、语音进语音出 | 双人/群聊 |
| 6 个场景，A2–B2 | 自定义场景编辑器 |
| 逐句三层复盘（表达 / 发音 / 更自然） | 发音总分、等级评定 |
| 卡壳点清单 | 通用句型库、每日一句 |
| 跟读关卡（3–5 词，音素级） | 实时纠音、语音动画 |
| 韵律指标趋势 | 学习路径规划、打卡 |

第一周：语音管线 + 场景对话 + 逐句复盘 + 卡壳点，发音只出韵律趋势。
第二周：跟读关卡接 Azure 发音评估，错词进复习队列。

> 第二周的发音功能长在第一周的数据上 —— 复盘里挑出来的可疑词，就是跟读关卡的输入。两件事不抢第一周的资源。

---

## 一、表达优先，发音分两层

「表达」和「发音」不是二选一，是**时间尺度不同的两件事**：

- **表达的瓶颈是检索**：想好了但词调不出来、句式没自动化、话轮接不上。只能在对话里练。
- **发音的瓶颈是可懂度**。而真正影响可懂度的不是音素，是**韵律**：

| 影响可懂度 | 不影响可懂度（只是口音） |
|---|---|
| 重音位置（`REcord`/`reCORD`） | /θ/ 发成 /s/ |
| 词尾丢失（worked 的 /t/、复数 s） | /v/ 发成 /w/ |
| 长短元音（ship/sheep、bad/bed） | 卷舌过度 |
| 句子重音、停顿位置 | 语调略平 |

**关键：韵律可以在对话里免费测，不需要参考文本。** WPM、停顿分布、词尾清晰度都能从音频本身算出来。只有音素级才需要「给参考文本 + 跟读」。

所以：

- **第一层 · 对话中（免费）**：只测韵律，不打分，复盘里说一句「今天你的停顿集中在从句开头」。
- **第二层 · 复盘后（付费）**：挑 3–5 个可疑词让用户跟读 → 这时有参考文本 → Azure Pronunciation Assessment 拿音素级诊断。

顺序不能反。一个「想说说不出来」的人，不会因为 /θ/ 发对了而留下；表达顺了才会开始在意发音。

## 二、场景：要有隐藏目标

没有目标，对话 20 分钟内必然塌缩回用户最熟的 20 个句式。

场景不是「话题」，是**带可完成目标的任务**。「说服对方给你退款」远比「练习购物对话」有效。

### 场景定义

```jsonc
{
  "id": "job-interview-1",
  "title": "第一轮面试",
  "level": "B1",
  "goal": "在三轮问答内说清楚最近一个项目和它的结果",
  "persona": "HR，节奏偏快，会追问细节，不说废话",
  "opening": "Hi, thanks for coming in. So, tell me a little about yourself.",
  "beats": [
    {
      "id": "intro",
      "need": "自我介绍（2–3 句，不是简历朗读）",
      "hint": "Give a 2-3 sentence summary, not your whole career.",
      "done_when": "用户提到了当前职位或最近一段经历"
    },
    {
      "id": "project",
      "need": "一个具体项目 + 结果",
      "hint": "Pick ONE project. What was the outcome?",
      "done_when": "用户给出了项目名或量化结果"
    },
    {
      "id": "followup",
      "need": "被追问细节时能顶住",
      "hint": "If you don't know, say how you'd find out.",
      "done_when": "用户回应了至少一次追问"
    }
  ],
  "key_phrases": ["I'd say...", "To give you an example...", "What I mean is..."],
  "difficulty": { "tts_speed": 1.0, "max_sentence_words": 18, "use_idioms": false }
}
```

`beats` 是 bot 的**隐藏议程**。每轮 LLM 输出里带 `beat_progress`，状态机据此推进。用户看不到这个结构 —— 他只会觉得「这个 HR 挺会追问的」。

### v1 场景清单

| id | 场景 | 级别 | 摩擦点 |
|---|---|---|---|
| `cafe-1` | 点单，店员听错了一次 | A2 | 重复、澄清 |
| `smalltalk-1` | 聊最近看的一部剧 | A2 | 开放式延续话题 |
| `job-interview-1` | 第一轮面试 | B1 | 结构化表达 |
| `standup-1` | 和同事同步项目进度 | B1 | 简洁、说清阻塞 |
| `return-item-1` | 电话客服退换货 | B1 | 高摩擦、有明确目标 |
| `pushback-1` | 拒绝同事的不合理请求 | B2 | 礼貌地不同意 |
| `interview-deep-1` | 面试被追问项目细节 | B2 | 顶住追问、不崩 |
| `meeting-1` | 会议中打断并提问 | B2 | 抢话轮 |

**bot 的语速也是教学杠杆**：A2 场景 TTS 0.9 倍速，B2 用 1.05 倍速。同一个场景也可以做成难度档。

## 三、纠错分级

每句都纠会直接摧毁开口意愿。

| 时机 | 做什么 | 强度 |
|---|---|---|
| 对话中 | **重铸**：用正确说法自然重复一遍，不点破 | 隐式 |
| 对话末 | 一句话点出最影响理解的问题 | 1 句 |
| 复盘 | 完整错题本，逐句对照 | 全量 |

重铸的实现：LLM 指令「如果用户的错误影响理解，在你的回复里自然地用上正确形式；绝不显式纠正」。同时把纠正记进 `flags`，给复盘用。

例：
> 用户：I very like this movie.
> bot：Oh nice, what do you like about it most? I really like the soundtrack myself.
> （自然用上 `really like`，不点破 `very like` 是错的）

---

## 四、复盘：以「句子」为单位，不以「能力维度」为单位

不做「发音 78 分 / 语法 5 个错」——用户看到抽象分数，不知道明天该干嘛。

做成**逐句三层**：

> **你说**：I very like this movie.
> **表达**：`very like` → `really like` / `like it a lot`（搭配问题，不是语法）
> **发音**：`movie` 的 /v/ 偏 /w/；`liked` 词尾 /t/ 吞掉了
> **更自然**：I'm a big fan of that movie.

同一句话，三层关系一眼可见，改起来也有抓手。

### 卡壳点：只有你能拿到的指标

对话中的失败分三类，价值完全不同：

| 类型 | 例子 | 价值 |
|---|---|---|
| 说错了但说完了 | `I very like` | 低，语法检查能搞定 |
| 说出来了但绕远 | 想表达「不好意思打断一下」，说了三句才到 | 中，改成一句就行 |
| **根本说不出来** | 停了 4 秒 / 换话题 / 冒出中文 | **最高** |

第三类才真正告诉你「下一批该学什么」，而它任何自动指标都算不出来 —— 只有「转录 + 停顿数据」能暴露。

复盘卡片里单独一栏「今天卡住的地方」，每个卡壳点直接生成一条待学句型。

## 五、指标

全部自动算，成本为零。存进多维表格，一次练习一行。

| 指标 | 定义 | 看什么 |
|---|---|---|
| 语速 WPM | 用户词数 / 用户语音总时长 × 60 | 80–150 舒适区；过低是检索慢 |
| 长停顿率 | >1.5s 的停顿数 / 分钟 | 下降 = 流利度在涨 |
| 填充词 | um/uh/erm/like 每百词 | 过高 = 语法自动化不足 |
| 词型/词例比 | 不重复词 / 总词数 | 词汇丰富度 |
| 主动词汇量 | 本次新用出的、之前没用过的词 | **最直接的进步证据** |
| 错误率 | 每百词语法错误数 | 与 WPM 一起看：快了但错多了 = 正常 |

**不要单独看任何一个。** 唯一值得设成目标的组合是：WPM 上升的同时错误率不上升。

---

## 六、输出策略

- **对话阶段不给文字**。给了人只读不听。
- **复盘阶段全给**。这时候需要精确的记忆锚点。
- **唯一例外**：故障兜底（TTS 挂了、ASR 没听清）时发文字。
