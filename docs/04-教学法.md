# 04 · 教学法

产品判断部分，来自原文 01，**基本保留**。这里只压缩掉 MVP 不需要的部分，并补两条原设计里缺的机制。

---

## 一、核心主张

> 这不是一个「会说英语的聊天对象」，是一个**有目标、有推进、有复盘**的练习系统。

三条设计红线：

1. **对话中不纠错**，只用重铸（recast）——用正确说法自然重复一遍，不点破。
2. **不给发音分数**，只给具体词、具体音。
3. **不做通用句型库**，只给「你刚才想说的那句」的更自然版本。

---

## 二、为什么必须有隐藏目标

没有目标，对话 20 分钟内必然塌缩回用户最熟的 20 个句式。

场景不是「话题」，是**带可完成目标的任务**。「说服对方给你退款」远比「练习购物对话」有效。

### MVP 只做一个场景：`cafe-1`

```jsonc
{
  "id": "cafe-1",
  "title": "点单，店员听错了一次",
  "level": "A2",
  "goal": "点一杯咖啡，并在店员听错后用一句澄清",
  "persona": "店员，节奏快，友好但话不多",
  "opening": "Hi! What can I get for you today?",
  "beats": [
    {
      "need": "点出饮品 + 一个定语（大小/冷热/奶）",
      "hint": "Try: Could I get a medium oat milk latte?"
    },
    {
      "need": "店员会听错一次，用户澄清",
      "hint": "Try: Sorry, I meant oat milk, not soy."
    }
  ]
}
```

**`beats` 是 bot 的隐藏议程。** 用户看不到，只会觉得「这个店员挺真实的」。

### 为什么是这一个

它有三个特征，缺一个都不行：

- **目标明确**，练习有终点
- **有摩擦**（店员听错），逼用户澄清 —— 这才是口语真正的难点
- **A2 水平**，第一次用就能完成，不至于开场就挫败

后面加场景时，照这个标准挑：**任务 + 摩擦 + 用户能把控的难度**。

---

## 三、纠错分级

每句都纠会直接摧毁开口意愿。

| 时机 | 做什么 | 强度 |
|---|---|---|
| 对话中 | **重铸**：用正确说法自然重复一遍，不点破 | 隐式 |
| 复盘 | 只挑 3 句，逐句对照 | 全量但有取舍 |

重铸的实现是**写进 system prompt 的指令**，不是代码逻辑：

> If the user makes an error that hurts understanding, work the correct form naturally into your reply. Never point out the error.

例：

> 用户：I very like this coffee.
> bot：Oh nice, what do you like about it most? I really like the soundtrack myself.

（自然用上 `really like`，不点破 `very like` 是错的）

---

## 四、重铸有个没解决的漏洞（原设计漏了）

**这是原文最大的遗漏，写在这里提醒。**

重铸的前提是「用户能注意到正确形式并自己领悟」。但对 A2 水平的耳朵：

```
I very like  →  I really like
```

差别在 `very` / `really` 这两个音高、重音都不同的词上。**没被点破的情况下，大概率注意不到。**

二语习得研究里，重铸对低水平学习者的效果本来就弱，需要 salience（显著性）才生效。你的产品在「不说破」和「用户感知不到」之间**没有机制**。

### 三条可选补救（选一条，不要都做）

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 提高显著性** | bot 重铸时把正确的那个词**略微放慢 + 加重** | 需要在 TTS 里做局部变速，MVP 做不了 |
| **B. 复盘里点名** | 复盘第一句写「刚才我重复了你的说法，用了 really 而不是 very」 | 一句话的事，**MVP 就该做** |
| **C. 结束后问一句** | 卡片上一个问题「刚才我重复过你原句的一个更好说法，你注意到了吗」 | 需要卡片交互，MVP 做不了 |

**MVP 选 B。** 成本最低，且能验证假设：如果用户看完 B 说「哦原来是这样」，说明重铸确实没被感知到，需要换策略。

> 这一条在 [archive/06-v1.1-开发方案 §三](archive/06-v1.1-开发方案.md) 里落地为「三句卡 + 强制热身」：不复述原句，而是**在开口前就给出正确说法**，绕开了「感知不到重铸」的问题。
>
> 注意：v1.1 里 B 方案**不单独占卡片一行**，由 `topIssue` 的「为什么」那行承担——所以 `why` 字段要按 B 方案的口吻写（「我重复了一个更好的说法」），不是泛泛的语法解释。

## 五、表达优先，发音分两层

「表达」和「发音」不是二选一，是**时间尺度不同的两件事**：

- **表达的瓶颈是检索**：想好了但词调不出来、句式没自动化、话轮接不上。只能在对话里练。
- **发音的瓶颈是可懂度**。而真正影响可懂度的不是音素，是**韵律**：

| 影响可懂度 | 不影响可懂度（只是口音） |
|---|---|
| 重音位置（`REcord`/`reCORD`） | /θ/ 发成 /s/ |
| 词尾丢失（worked 的 /t/、复数 s） | /v/ 发成 /w/ |
| 长短元音（ship/sheep） | 卷舌过度 |
| 句子重音、停顿位置 | 语调略平 |

**关键：韵律可以在对话里免费测，不需要参考文本。** 只有音素级才需要「参考文本 + 跟读」。

所以顺序不能反：

1. **第一层 · 对话中（免费）**：只测韵律（停顿、语速、填充词）
2. **第二层 · 复盘后（付费）**：挑 3–5 个可疑词跟读 → Azure 发音评估拿音素级诊断

一个「想说说不出来」的人，不会因为 /θ/ 发对了而留下；表达顺了才会开始在意发音。

**MVP 只做第一层。**

## 六、卡壳点：最值钱的指标

对话中的失败分三类，价值完全不同：

| 类型 | 例子 | 价值 |
|---|---|---|
| 说错了但说完了 | `I very like` | 低，语法检查能搞定 |
| 说出来了但绕远 | 想表达「不好意思打断一下」，说了三句才到 | 中，改成一句就行 |
| **根本说不出来** | 停了 4 秒 / 换话题 / 冒出中文 | **最高** |

第三类才真正告诉你「下一批该学什么」，而它任何自动指标都算不出来 —— 只有「转录 + 停顿数据」能暴露。

**这也是为什么词级时间戳是 MVP 的硬依赖。** 没有它，卡壳点识别不了，产品退化成「带总结的聊天机器人」。

### MVP 的简化

只做两个廉价信号（从词级时间戳直接算）：

| 信号 | 判定 |
|---|---|
| 长停顿 | 相邻词间隔 > 1.5s |
| 轮首长静音 | 音频开头到首词 > 2s |

`self_repair`（说到一半改口）、`topic_switch`（卡住后换话题）需要 LLM 参与，第一版不做。

---

## 七、输出策略

- **对话阶段不给文字。** 给了人只读不听。
- **复盘阶段给卡片**，但不给全文——只给 3 句。全量留到第二周。
- **唯一例外**：故障兜底（TTS 挂了、ASR 没听清）时发文字。

---

## 八、v1 之后才做的事

按价值排序，MVP 验证「想不想练第 4 次」之后再逐条评估：

| 项 | 前提 |
|---|---|
| 第二个场景 | 第一个场景被练了 3 次以上 |
| 跟读关卡 + Azure 发音评估 | 攒够了可疑词 |
| 复习队列 | 有跨会话的错词可复习 |
| 飞书文档复盘 | 卡片明显不够用 |
| 韵律趋势图 | 有 5 次以上的数据 |
| 双人 / 群聊 | 自用跑通之后 |

**不要按这个顺序规划，按实际卡在哪里决定。**
