## 二、这几天的观察任务

**先别改代码，攒 8–10 场。** 同一场景反复练更有价值——能看出「同样的错误会不会反复」。

### 要看的五个数

| # | 看什么 | 从哪看 | 判断标准 |
|---|---|---|---|
| 1 | `agreement` 分布 | `postmortem.json` 的 `sentences[].agreement` | 大量低于 0.67 说明 sampler 还不够，要加到 5 次 |
| 2 | `unclear` 占比 | `counts.unclear / 总句数` | 超过 25% 说明 `verifySentence` 的降级条件太宽 |
| 3 | 四档比例 | `counts` | `~` 接近 0 说明判得太保守；`✗` 过半说明太严 |
| 4 | `beatsMissed` 频率 | 同上 | 超过三分之一说明 beat 靠 prompt 管不住，要改代码强注入 |
| 5 | `/end` 等待 | 体感 + `trace` | 超过 15 秒就要降采样次数 |

### 要手记的一件事

**觉得卡片说错的时候，记下「哪一场、第几轮、它说了什么、你觉得应该是什么」。**
这比任何自动指标都值钱——判分规则的每一条都是这么定下来的。

## 三、已知没修的问题

按影响排序。**都没动，等数据说话。**

| # | 问题 | 现在怎样 | 为什么要等 |
|---|---|---|---|
| 1 | **热身抽词会歪** | `Nice, a large isomeric.`——在肯定一个不存在的词 | 一次改动同时影响卡片文案和块统计，先确认它在真实使用里有多碍事 |
| 2 | **店员可能不做 beat** | 复盘如实标出来，但不强制 | 看 `beatsMissed` 频率再决定是改 prompt 还是改代码 |
| 3 | **三句卡永远是那三句** | `alternatives` 只用于匹配，不显示；热身永远「用 1 号句造一句」 | 用户提过，但优先级排在判分之后 |
| 4 | **同一个场景没有变体** | `cafe-1` 固定一种练法 | 变体轴（饮品 × 杯型 × 冷热 × 摩擦）比多生成 10 个场景更能回答「会不会练第 4 次」 |
| 5 | **词汇量少的人还是会卡住** | 没有词块预习，bot 提问也不埋答案 | 依赖 #3 和 #4 |
| 6 | **`unclear` 的理由可能写错** | 档位对，`why` 偶尔把「习惯问句」当「过去时」 | 不影响用户判断对错，最后调措辞 |

## 四、被砍掉的和被推迟的

| 项 | 决定 | 理由 |
|---|---|---|
| `wordStretch` / `spanRatio` | 不做 | 「能不能说出来」不用音频指标，转录就能算 |
| P1.5 步 3–4（场景生成落盘 / 分类合并） | 继续挂起 | 生成的场景照样是 3 个固定 frame，还会把 beat 弄丢 |
| 语速（`wpm`）上卡片 | 砍掉 | 用户说语速不重要，重要的是说得出来、说得对、说得地道 |
| 两个话题同时说 | 不做 | 正常只练一个话题；代码仍按 `sessionKey` 分开排队 |
| `cardStyle: rewrite` 的第三种 | 不做 | 现在 `blocks` / `rewrite` 够用 |

## 五、代码地图

```
src/
├── index.ts      入口：收消息 → 分派 → 发语音 / 发卡片
├── pipeline.ts   一轮的编排（转码 → ASR → LLM → TTS），落盘
├── grading.ts    逐句评分。一句一调、三次采样投票、unclear 由代码定
├── review.ts     复盘：buildPostmortem（数据）+ renderCard（文案）
├── blocks.ts     三句卡的匹配派生、块使用统计
├── beats.ts      bot 的隐藏议程，听错换词在这里
├── scenarios.ts  场景加载 / 校验 / 选题路由 / 三句卡渲染
├── warmup.ts     热身那句模板（不调 LLM）
├── llm.ts        对话轮：只出 say
├── asr.ts / tts.ts / lark.ts / topic.ts / flow.ts
└── probe-llm.ts / probe-scenario-gen.ts   诊断工具，不进运行时
```

`grading.ts` 和 `review.ts` 是 2026-10-26 新增 / 重写的，读代码从这两个开始。

## 六、快速自检

```bash
pnpm check        # 纯本地，不联网
pnpm typecheck    # tsc --noEmit
```

`pnpm check` 覆盖：块的匹配派生、场景校验、flow 分派、指标 null 语义、
`verifySentence` 的四档降级规则、卡片渲染（含判分全挂时仍出卡片）。

**判分质量没有自检**——它要联网，只能在真机上攒数据看。
